## Problem Statement

An instructor (university business school) needs an in-person paper MCQ exam that is harder to share via class Instagram (e.g. bathroom posts of “Q3 = B”). He wants one-page **personalized exam sheets** (question text + bubbles on the same Letter page) with QR, shuffled order/options, number-only variants inside questions, phone bubble scan, and class CSV export.

Provenance: instructor Q&A (self-reported requirements) (self-made bank, 10 MCQ, numbers only, phone bubbles, prototype desktop CSV, ~40 students; columns name, id, answers-by-question).

## What Makes This Cool

Same 10 stems, different numbers and different A–D mappings per student — so a leaked “answer key” from Instagram does not transfer. One private link: upload → print → photo → CSV.

## Constraints

- Side project for instructor review, not a startup platform
- ~40 students/class (cap 50 in MVP)
- All bubble MCQ; Letter one-page PDF
- Prototype: web camera/upload, not native app; not LMS
- Structured question bank only (no Word/PDF parse)
- Student IDs sensitive: private unguessable link; **no real student data** in git, screenshots, or public demos
- First usable grading path may be QR + **manual** bubble entry; auto ink estimate is additive

## Premises

1. Core pain is reusable Instagram answers, not perfect anti-cheat.
2. The instructor can use a structured bank table for MVP.
3. Success = the instructor completes upload → print → photo → CSV and gives feedback; not official-grade auto CV.
4. Need end-to-end web generation + grade UX; desktop-only OMR tools alone are insufficient.
5. Private link OK for trial; harden auth before real graded use.

## Approaches Considered

### Approach A: Minimal closed-loop Web App (chosen)

One deployable web app: roster + bank CSV → per-student Letter PDF + stored answer maps → photo/QR (+ optional coarse bubble read) → manual fix → CSV.

### Approach B: Ideal architecture — rejected

Full auth, sessions, server OMR queue, audit — too slow for a review link.

### Approach C: Generate-first, grade later — rejected

Fastest print path but conflicts with the instructor’s phone-scan grading ask for the prototype story. (MVP still sequences **generate first**, then grade UI; auto-OMR is not a blocker for first demo.)

## Recommended Approach

**Approach A.** Initial stack (locked for MVP): **Cloudflare Pages + Workers + D1** (fits “CF Pages OK”; Workers for PDF/grade APIs; D1 for token-scoped instances). Swap to Vercel only if CF runtime blocks a required library.

### User flow

1. Open private exam link (`/e/{token}`). **Every** read/write API requires that token (header or path); unknown token → 404.
2. Upload `students.csv` and `bank.csv`. Validate before generate (see below). Failures show row-level errors; **no partial generate**.
3. Click Generate → **ZIP of PDFs** (MVP delivery; browser print-all deferred). Each **personalized exam sheet**: name, id, QR(`exam_instance_id`), 10 rendered questions + A–D bubbles, four corner fiducial markers.
4. After exam: Upload photo → read QR → open grade form prefilled if auto-estimate available, else empty → the instructor confirms/edits → Save.
5. Download results CSV (schema below).

### Token / privacy

- Token: 128-bit random; **store only SHA-256 hash** in D1; compare hash on each request. Raw token only in the instructor’s URL.
- `Referrer-Policy: no-referrer` on app; no third-party scripts/analytics on exam routes.
- Never log raw token, roster, or answers.
- MVP: support **revoke** (delete/invalidate hash → API 404).
- Sample CSVs in repo use fake names/ids only.

### Question bank schema (MVP)

| column | meaning |
|--------|---------|
| question_id | stable id (export key) |
| stem_template | text with `{n1}`, `{n2}`, … integers only |
| n1_min, n1_max, … | inclusive integer ranges; required for each `{n*}` used |
| choice_a_template … choice_d_template | option text; may include `{n*}` |
| correct_choice | `A`–`D` in **canonical (pre-shuffle)** labeling |

**Invariant:** For every legal sample of `{n*}`, the canonical `correct_choice` remains the uniquely correct option. MVP enforcement: (1) reject non-unique rendered choices; (2) for each question, if the cartesian product of ranges is ≤ 200, enumerate and assert `correct_choice` stays valid as author-declared (author still responsible for semantic truth); if product > 200, sample 32 random draws and assert unique choices + declared letter still in {A–D}. Full semantic proof of “right answer” is out of scope without an answer expression language.

**Template rules:** Only `{n1}`…`{n8}` placeholders; no expressions/formulas in MVP. Literal `{` / `}` in prose not allowed in MVP (keep stems plain).

**Example bank row:**

```csv
question_id,stem_template,n1_min,n1_max,choice_a_template,choice_b_template,choice_c_template,choice_d_template,correct_choice
q_switch,"If customer switching cost is about {n1} months of revenue, which force usually strengthens?",1,6,Buyer power,Supplier power,Threat of substitutes only,None of the above,A
```

Prefer items where sampled numbers personalize the stem but **do not flip** the keyed letter (matches the instructor’s “only changing the numbers”).

### Bank file validation (before generate)

- Exactly **10** data rows; **unique** `question_id`
- Required columns only (unknown columns → error)
- Each `{nk}` used in stem/choices has `nk_min`/`nk_max` integers with min ≤ max
- `correct_choice` ∈ {A,B,C,D}
- Row-level errors; **no partial generate**

### Roster validation

- Required columns: `student_name`, `student_id`
- 1–50 rows; non-empty name/id; **unique** `student_id`
- Trim whitespace; reject otherwise with row numbers

### Generation per student

1. Sample integers per question from ranges.
2. Render stem/choices; enforce unique choice strings.
3. Shuffle question order; shuffle choice order; store maps under `exam_instance_id`.
4. PDF Letter: if content overflows one page (stem/choice length), **fail that generate** with “shorten bank text” — do not silently spill to page 2 in MVP.
5. Soft limits (guidance): stem ≤ 280 chars rendered; each choice ≤ 100 chars.

### Anti-cheat model

- Entire class shares the same 10 `question_id`s (not different draws).
- Per sheet: independent number draws, question permutation, choice permutation.
- QR encodes only random `exam_instance_id` (D1 lookup); no PII in QR.

### Grading model (phased)

**Phase G0 (required for demo):** QR identify → the instructor selects A–D (or blank) per **printed** question → save.

**Phase G1 (same MVP if time):** ink-ratio estimate from aligned sheet; low confidence / multi-fill / empty → leave blank and flag `needs_review`.

**Statuses:** `ok` | `needs_review` | `unreadable_qr` | `wrong_exam` | `duplicate_upload`

**Actions:** re-upload; manual entry; skip sheet; if duplicate `exam_instance_id`, keep latest with audit note in UI.

**Scoring:** For each `question_id`, map selected printed letter → canonical choice via stored shuffle map; compare to `correct_choice`. Unanswered = incorrect. Score = correct count / 10. No partial credit.

### Results CSV

Columns:

- `student_name`, `student_id`
- `ans_<question_id>` for each bank id (canonical letter **after** map-back, or empty)
- `score_correct`, `score_pct`, `status`
- Optional: `printed_order` JSON omitted from the instructor’s default export; power users can ignore

Default export matches the instructor’s ask (name, id, answers-by-question) using stable question ids, not “position 1–10”.

### Image / OMR notes (G1)

- Accept JPEG/PNG; max ~8MB; client may downscale.
- Fiducials at four corners; bubbles in fixed grid relative to markers.
- Confidence below threshold or multi-mark → no auto letter (manual).

### Out of scope (MVP)

- Per-student different question draws
- Word/PDF bank import; template expressions
- Multi-instructor SaaS, LMS sync
- Native apps; Scantron parity
- CI/CD polish beyond “can deploy once” for the instructor’s link (automate after first successful demo)

## Success Criteria

- The instructor generates a ≤40-student exam from sample or his bank+roster in one sitting; receives ZIP of PDFs.
- Two sheets show different numbers/option orders for the same `question_id`.
- He grades ≥3 sheets via QR + manual (or assisted) UI, including one messy photo path (`needs_review` / re-upload).
- Downloads CSV with name, id, per-`question_id` answers, score.
- He replies with concrete change requests.
